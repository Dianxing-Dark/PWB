# 3D 检查点与失败恢复

| 任务 | 参考检查通过 | 从默认入口完整通关 |
| --- | ---: | ---: |
| A10 上下层检查点 | 6/6 | 无计划 |
| C07 陷阱与检查点 | 7/7 | 无计划 |
| C12 双房间恢复 | 12/12 | 2/2 |

上下层检查点共用水平投影，两处重生位置高度相差 2.2 米。C07 从默认入口实际登记下层和上层检查点，再触发上层陷阱并恢复到第二处检查点。C12 的正常旅程需要先启动下层供电，再启动上层开关，最后进入出口。重试旅程要求下层供电保留、上层开关清空并重新激活。另用未供电和已供电但上层开关关闭两个起始流程测试出口条件。

| 注入故障 | 检出位置 |
| --- | --- |
| 上层接触登记成下层 | 上层登记、坠落重试和标记反馈 |
| 上层登记正确，重生高度错误 | 坠落重试 |
| 标记和 HUD 保持初始状态 | 检查点视觉反馈 |
| 下层陷阱错误影响上层安全通道 | 经过下层陷阱投影的上层通行 |
| 重试总使用第一次登记 | 同一尝试内先后登记两个检查点 |
| 重试清掉下层供电 | 重试状态和恢复旅程，直接旅程通过 |
| 重试保留上层临时开关 | 重试状态和恢复旅程，直接旅程通过 |
| 出口忽略两个开关 | 两个出口负例，两个正常通关旅程通过 |
| 出口仅检查下层供电 | 供电开启、上层开关关闭的负例 |

局部状态验证和完整旅程并行登记，参考 [CEGame-Bench 的旅程、评分与校准协议](https://arxiv.org/html/2610.26098v1)。检查点、终态和重试使用带仿真步号的事件与动作前后快照，参考 [WorldCoder-Bench StateProbe](https://arxiv.org/html/2606.01869)。真实输入、合法局部预置和事件截图沿用仓库现有协议，可对照 [GameASG 的 L2 执行代码](https://github.com/areal-project/GameASG-Bench/tree/6427cb6517ce11ff350ec45fcae17b67c5aec245/scripts/l2) 与 [GameCraft 的回放评分代码](https://github.com/FreedomIntelligence/gamecraft-bench/blob/d64cc5d817bd331a840a378e6e42c873b1139055/gamecraft_bench/verifier/score.py)。

合同检查、试玩与视觉、完整评测在这九个定向故障上分别检出 8、4、9 个。两轮运行的用例判定一致。详见 [校准记录](calibration.json) 和 [三种评测组合的判定](profiles.json)。

恢复证据可以从 [下层已登记](c07-lower-saved.png) 看到 [按 R 后返回上层](c07-retry-upstairs.png)。C12 的 [恢复画面](c12-after-retry.png)显示供电保留、上层开关空闲，[胜利画面](c12-victory.png)显示上层开关重新激活。

## 复现

    npm ci
    node scripts/play-checkpoints.mjs C12
    node scripts/evaluate-checkpoints.mjs --calibrate

浏览器中使用 WASD 移动、E 操作、R 重试。报告保留可信浏览器输入、事件顺序与截图哈希。当前三项任务共用一套参考场景与模拟实现。独立等价实现、空壳对照和这一任务族的生成基线仍待补齐。
